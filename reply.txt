1. The core implementation of the proposed method, including the dynamic packing component.
Reply: The core implementation of the proposed method can be found in both the system implementation repository “https://github.com/apache/tsfile/tree/research/encoding-pack-size/java/tsfile/src/test/java/org/apache/tsfile/encoding/OptimizePackSize.java“
and the experiment reproducibility repository “https://github.com/thssdb/encoding-pack-size/tree/main/src/OptimizePackSize.java”.
In particular, the dynamic packing component is implemented in “OptimizePackSize.java”, within the method DynamicPacking (Lines
698-823).

2. The scripts, configuration files, and instructions needed to reproduce the main reported experiments, to the extent possible.
Reply: The scripts to reproduce the main reported experiments can be found in the table “Quick lookup of script” of “https://github.com/thssdb/encoding-pack-size/tree/main/README.md“
For example, the scripts of producing the results of Figure 17 are the functions “BPAll()”, “BPAllSort()”, “BPPruneRMQ()” and “BPPruneR-
MQSort()” of “https://github.com/thssdb/encoding-pack-size/tree/main/src/OptimizePackSizeSort.java”. 
The configuration file is “https://github.com/thssdb/encoding-pack-size/tree/main/scripts/bootstrap_env.sh”. We can run the following
commands to configure the environment.
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
The instructions on how to use the scripts to produce experiment results, e.g., Figure 17, are as follows.
cd {basedir}
mvn test '-Dtest=OptimizePackSizeSort#BPAll+BPAllSort+BPPruneRMQ+BPPruneRMQSort'
python3 fig17_vary_pack_size_sort.py
Here, “basedir” is the local directory of the ‘encoding-pack-size‘ project.
The aforementioned scripts, configuration files, and instructions can also be found in “https://github.com/thssdb/encoding-pack-size/tree/main/README.md“


3. A clear README indicating the exact branch, commit, and commands to run.
Reply: For the code repository of system implementation, the exact branch of the proposed method is “https://github.com/apache/tsfile/tree/research/encoding-pack-size“.
The commit hash is dabbb4176f80f2a3f33a4acdca500ba2296e9d14. And the following commands test the system implementation, and produce the tsfile compressed by Bit-packing with optimal pack size.

4. A pointer to the code path used for the floating-point experiments, together with a clarification of whether the floating-point-to-integer
conversion used in those experiments is lossless.
Reply: The code for the floating-point experiments is located in “https://github.com/thssdb/encoding-pack-size/tree/main/src/FloatToInteger.java”.
When the processing dataset is floating-point, it first calls the scaling function “long[] scaleNumbers(List<String> numbers, int decimal-
Max)” in lines 37-66 of “FloatToInteger.java”. Once the floating-point-to-integer conversion is done, it is processed the same as integer
datasets.
Note that each dataset has a maximum number of significant digits after the decimal point, i.e., k in scaling float point to integer in Section
4.1.2. Thereby, the floating-point-to-integer conversion used in those experiments is lossless. Nevertheless, “FloatToIntLosslessTest()”, in
Lines 68-152 of “FloatToInteger.java”, can verify the correctness in the experiments.
